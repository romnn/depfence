# 1. Rules query the resolved package graph instead of cargo-deny's wrappers

**Status:** accepted · **Date:** 2026-11-23

## Context

cargo-deny's `bans` check is edge-local.
`{ crate = "X", wrappers = ["W"] }` says that W may depend on X directly and nobody else may.
It cannot say that a package must not reach X by any path.
Once W is an allowed wrapper, every crate that depends on W reaches X, and cargo-deny reports the
graph as clean.
Closing that gap with `wrappers` alone means guarding the whole transitive closure, which can reach
workspace roots that no wrapper can name.

Other tools cover neighboring ground but not these rules: cargo-deplint denies transitive paths
from `Cargo.lock` without distinguishing dependency kinds, cargo-depgraph-check allowlists direct
edges between workspace members, and cargo-pup, arch-lint and cargo-layers work on modules inside a
crate.

## Decision

depfence resolves the workspace with Guppy and evaluates three rule kinds against that graph:

- `forbid` rejects any normal or build dependency path from a root to a forbidden crate, judged on
  the all-features graph, or only on the edges the selected features activate when the rule
  selects features.
- `restrict` limits the direct dependents of a guarded crate, with prefix globs, most-specific-rule
  precedence, and an opt-out for dev-only edges.
- `deny-feature` rejects a feature that a simulated `cargo test --workspace --all-features` enables
  for target code, leaving build scripts and proc macros free to enable it.

Every rule judges all platforms at once, so a reported path can join edges that no single build
follows.
`forbid` also joins host and target edges, while `deny-feature` keeps them apart and assumes Cargo's
feature resolver 2 or later.

Entries that name a crate or feature missing from the graph are reported as stale, and fail the
check under `--strict`.
A glob that matches nothing is not stale, and neither are the `only` entries of a `restrict` rule
whose glob matches nothing, because a glob can guard against crates that do not exist yet.
The tests in `crates/depfence/src/cargo/` pin each rule's semantics.

## Consequences

- depfence depends on Guppy, which is pre-1.0, for graph queries and Cargo's feature resolution.
- It overlaps with cargo-deny's `wrappers` and feature bans; projects keep cargo-deny for duplicate
  versions, licenses, advisories and sources.
- A workspace-hack package generated by cargo-hakari is skipped by `forbid` and `restrict`, because
  its edges reach every dependency from every member without saying which crate uses what.
